# Interview Notes — FinOps Cloud Cost Visibility

## Project objective
Provide a simple view of cloud usage and estimated costs, show budget utilization, and flag configured usage thresholds so a learner can practise cost monitoring before connecting a real provider billing source.

## Architecture
Browser (HTML/CSS/JavaScript + Chart.js) → Flask routes / JSON API → SQLite. The `/metrics` endpoint is scraped by Prometheus; Grafana reads Prometheus and visualizes application metrics. CSV export is generated by Flask.

## Data flow
1. Initialize SQLite and seed demo records on first start.
2. Browser calls `/api/dashboard` and `/api/usage`.
3. Flask aggregates the current month's costs and latest per-service usage.
4. Risk rule marks Watch at >=70% and High at >=90% of configured demo limits.
5. Browser renders KPIs, line chart, doughnut chart, alerts, and table.
6. User downloads weekly CSV or edits the monthly budget.
7. Prometheus scrapes `/metrics` every 15 seconds when optional stack is enabled.

## Be transparent
The current version uses simulated data. It does not call AWS Cost Explorer or GCP Billing yet. Do not tell interviewers it is a live billing integration. Explain the next step: add a provider adapter using least-privilege credentials, verified quotas/pricing, delayed-billing caveats, tests, and provider-side alerts.

## Potential next iterations
- AWS Cost Explorer API adapter and GCP BigQuery billing export adapter.
- Background ingestion job and idempotent upserts.
- Alert destinations (email/Slack) with deduplication.
- Authentication, role-based access, secret manager, deployment, and CI pipeline.
- PostgreSQL for multi-user production use.
